Initial Setup & Configuration

Welcome to the LED Pixel Mapper technical reference manual. This document provides detailed, step-by-step instructions for configuring project parameters, routing data, managing power distribution, establishing system redundancy, and generating technical documentation.

1.1 Software Activation

To access the full suite of features, your installation must be authenticated. Navigate to the top-left menu bar, select File, and click on the Licensing tab. Input your administrative license key and select Verify. Upon successful authentication, the system will display a "License Activated - Pro" confirmation prompt.

1.2 Project Details & Color Depth

The Landing Page serves as the primary configuration matrix for your setup. Under the Project Details heading, name your first canvas and select the global processing mode:

  • 8-bit Mode: Standard color depth mapping. Yields higher port processing capacities.
  • 10-bit Mode: High-dynamic-range color depth. Note: Selecting this mode fundamentally alters and reduces the pixel capacity limits on all processor data ports. Pro
  • 12-bit Mode: Maximum color depth, drawn from each manufacturer's published loading charts rather than a flat multiplier — NovaStar COEX 1G and the MCTRL4K use the ×48 formula, COEX 5G halves the 8-bit budget, Brompton Tessera runs at two-thirds (with Ultra Low Latency halving it again), and Megapixel HELIOS follows its own 12-bit column. Port capacities update accordingly, and the EDID exporter defaults to RGB 12-bit to match. Pro

Bit depth and frame rate are what every port budget is calculated from, so changing either one resizes every port in the project at once. If a change would push ports you have already routed past their new limit, a dialog names each one before anything is applied — processor, port, how far over it would be, and how many tiles would have to come off — with a Cancel. A change that costs you nothing is applied straight away with no interruption. The check uses the same rule the routing block enforces, so it cannot tell you one thing and then have routing do another.

ℹ️
Legacy processors and 12-bit Legacy NovaStar, H Series, and generic processor profiles have no published 12-bit loading chart. For these, 12-bit is treated the same as 10-bit until manufacturer figures are available.

1.3 Canvas Resolution & Multiple Canvases

Define the physical or conceptual workspace for your LED wall using the Canvas Resolution module. You may select from industry-standard aspect ratio presets, or utilize the Custom tab to manually input bespoke horizontal and vertical pixel dimensions corresponding to your specific stage design.

A single project file can hold several canvases, listed along the bottom tab bar — one per screen, room, or scenic element. Use ⧉ Duplicate on any tab to make a complete deep copy of that canvas including every wall, tile, port, circuit, and route; it is named "<canvas> (Copy)" and becomes active immediately. This is the fastest way to trial an alternate routing or power scheme without disturbing the approved version.

ℹ️
Canvas names and the file name are separate Naming a canvas does not name your saved file, and vice versa. Canvas names live in the bottom tab bar; the project file name is shown in the top toolbar and is set the first time you save (defaulting to "Untitled Project"). Projects save as .lpmap — older .lpmap.json and .json files still open and save over correctly.

Canvas tabs hold their position in the bar. Switching canvases moves the highlight, not the tabs — the one you are working on does not jump to the front — so the bar stays as you arranged it and you can find a canvas by where you last saw it. Drag a tab to reorder them, and that order is saved with the project and used by every export. The + that adds a canvas sits at the end of the row, after the last tab; the wall tab bar works the same way.

Every wall carries its own colour. Click the colour dot on a wall tab to set it, or set it from the export dialog — either way the wall tabs, the Select-mode canvas and every export follow the same value, so they can never disagree. It is saved with the project, it is undoable, and a wall you have not set keeps the palette colour for its position.

While in Select mode, every wall other than the one you are working on displays a small name badge over each cluster of its tiles. When a wall's pieces are scattered across the canvas — a header, two side towers, and a floor strip, say — this makes it immediately clear which piece belongs to which wall. The active wall stays unmarked so it remains clean to work on, and the badges hold a constant on-screen size at any zoom level. They can be switched off from the canvas toolbar beside the snap controls, and that choice persists across sessions. The badges now show in all three modes — Select, Routing and Circuiting — rather than Select alone.

1.4 Hardware Library Configuration

Before routing data, you must populate your project with the appropriate physical hardware:

  • Adding LED Tiles: Under Tile Profiles, click Library to open the 2,700-panel catalogue in its own window. Brands run down the left with a count each, one search box matches brand, model and resolution together, and every panel is a card showing what actually separates one from another — pitch, pixel count, real size in millimetres, power draw. Each card draws the panel's own proportions to scale against the others on screen, so a 500 × 1000 reads as twice the height of a 500 × 500 without you comparing numbers. For proprietary or unlisted hardware, Add Custom still takes the name, pixel width and height, physical size, and maximum power draw by hand.
  • Adding Processors: Add on the Processors header opens a picker window. Search matches model, range or port count — "MX40", "tessera" and "20 ports" all find hardware — ranges run down the side with counts, and every model is shown with a drawing of its real front panel, so you can pick out the box you have in the rack instead of working from model numbers. All 45 models are drawn: the NovaStar MCTRL / MSD / NovaPro, VX and VX Pro ranges, the COEX MX controllers, the H Series, Brompton Tessera, and Megapixel HELIOS. Your saved My Processors get their own section, and building one by hand is one click.

    The window picks a model only. Naming, expander boxes and H-Series output cards stay on the form behind it, because those configure one particular processor rather than browse for one.
  • Modular Processor Trees: H Series and COEX processors build a Card ▸ CVT box ▸ ports tree. Choose which output cards go in each chassis slot (copper, direct to wall, or fiber, fanning out to CVT expansion boxes), and how many CVT boxes each fiber card drives. Double-click any card's name in the routing panel to give it a custom label — e.g. "Front Truss FOH" — which then appears everywhere that card is referenced, including the Redundancy Planner and the PDF report.
  • Removing a panel profile: the bin beside a tile profile deletes that panel and every tile on the canvas built from it. A tile has no size, pitch or power of its own — all of that lives on the panel — so it cannot outlive the panel it is drawn from. You are told how many tiles will go before anything happens, those tiles are unrouted from their ports and circuits on the way out, and the whole thing is a single Ctrl+Z. To change a wall from one panel to another without losing the layout, use Replace Panel from the profile's right-click menu instead.
  • Saving Custom Hardware Pro — Save a custom tile or a configured processor to your personal library with the ★ button; it's then available across every project. Saved tiles and processors can be edited in place at any time from the library list.
ℹ️
Note on Hardware Flexibility Hardware configuration is fully non-destructive. Additional tiles and processors can be appended directly within the Canvas Page later in the design process if the scope of the project expands.

1.5 Global Preferences

The Preferences menu applies project-wide settings that follow you across every project you open:

  • Theme: Toggle between Dark and Light mode.
  • Port Naming Convention: Choose Letters (A, B, C…) or Numbers (1, 2, 3…) for auto-generated port names. Switching instantly renames every auto-generated port across every processor and canvas — manually renamed ports are left untouched. Your choice is also applied when a project is opened and after any processor or expander box is added, so an older project adopts your convention without you having to toggle the setting. Brompton SX40 trunks remain lettered (A1–D10) regardless, matching the hardware's own labelling.
  • Low / High Voltage: Set your region's voltage standards (100V/110V/120V/Custom low, up to 220V/240V high) — every amperage calculation, circuit panel display, and export reflects your setting.
  • Measurement Units: Metric (mm/cm/m) or Imperial (ft/in), used by the Technical Drawing export and physical wall size labels.
  • Advanced Port Capacity Overrides: two opt-in toggles for when the published figures are more conservative than your rig actually needs. Allow full network port capacity lets a 1G port fill to the physical Cat5/gigabit ceiling of 655,360 px instead of stopping at the sender's published number — 8-bit only, because at 10- and 12-bit a pixel costs more bits on the wire. Frame rate affects NovaStar legacy port capacity makes MCTRL / MSD / NovaPro / VX senders scale with frame rate — roughly double at 30 Hz, about 1.2× at 50 Hz — rather than applying one figure at every rate. Both are off by default and neither can ever reduce a port's capacity.
⚠️
What the overrides trade away The published per-port figures carry the manufacturer's own headroom. Turning an override on spends that headroom, and each toggle says on screen what you are giving up. Leave them off unless you have a specific reason and the rig to back it up — the defaults are what the manufacturer will support.

The left and right side panels can also be resized by dragging their divider, and collapse automatically to give the canvas more room while routing data or power.

1.6 Undo, Confirmations & Icons

Ctrl+Z reaches everything in the project — layout, routing, circuits, redundancy, names and colours. Actions that touch several things at once are a single undo rather than one per change: finishing the Brompton wizard, swapping a processor, deleting a panel and its tiles, or renaming a Soca and its six circuits each reverse in one keystroke.

Deleting anything asks first. Walls, canvases, circuits, Socas, circuit groups, data ports, processors, panel profiles, and saved My Tiles / My Processors each put up a single question naming what you clicked. Where the consequence goes beyond the thing itself, the question says so — a Soca names how many circuits go with it, a panel profile names how many tiles on the canvas go with it, and a circuit group tells you its contents move up a level rather than being deleted. Cancel takes the focus, so Enter and Esc both back out safely.

⚠️
Two things undo cannot reach My Tiles and My Processors are your personal library, stored with your preferences rather than in the project, so Ctrl+Z does not reach them. Their confirmations say plainly that the deletion cannot be undone.

Icons mean one thing each throughout the app: an ✕ closes, dismisses, clears or unassigns, and a bin deletes. Removing a tile from a circuit or a port keeps its ✕, because that unassigns the tile rather than destroying it. Previously both jobs used an ✕ and the two sat side by side on the same rows.

Data Routing & Port Management

The Routing Tab provides the interface for mapping processor outputs to individual LED tiles on the canvas. Accurate routing is critical for proper image rendering and processing load distribution.

2.1 Processor Initialization & Peripherals

Upon entering the Routing interface, the right-hand panel displays your active processors. Selecting a processor expands its configuration parameters. If your system architecture utilizes optical fiber extensions (e.g., Novastar CVT boxes), they can be appended to the processor here. Doing so updates the interface to reflect the modified port topography.

2.2 Port Configuration

All available outputs are listed beneath the active processor. To maintain optimal organization in multi-wall setups, individual ports can be explicitly assigned to specific walls. Selecting the color indicator adjacent to the port name permits color-coding, which will dynamically reflect across the canvas and export documents.

Naming a port: double-click any port chip to rename it in place — up to 16 characters, with your capitalisation preserved, so an output can carry the name the crew actually uses on site ("Stage L", "Main", "Upstage Header") rather than a generic letter. A custom name appears on the canvas tile label, on cable labels, and throughout the PDF and CSV reports. It is also protected: changing the Numbers/Letters preference renumbers only auto-generated ports and never overwrites a name you typed.

Processor IP address: each processor header carries an optional IP field. When set, the address prints beneath the processor name in the PDF's Processor Requirements table and occupies its own column in the production CSV — so the network configuration travels with the paperwork instead of living in a separate note.

Whole-device capacity on COEX controllers

A controller is rated for less than its ports add up to. An MX40 Pro's twenty ports total 13.2M pixels — 26.4M with four CVT boxes — but the device itself stops at 9.00M at 60 Hz. The published per-device figure is enforced for every COEX model, by frame rate, bit depth and receiving-card class. Routing blocks at the device limit naming the controller and its rating, and the processor header carries a device-total bar that runs amber then red. A device can go over its rating while every single port on it is individually legal, which is exactly the case this catches.

Where the manufacturer's tables are ambiguous the rating under-claims rather than guesses upward: an unlisted frame rate rounds up to the next published one, an unsupported combination falls back to the lowest figure that device publishes, and mixed receiving cards are rated by the lower class. A model with no published rating is left alone.

Free Topology (NovaStar VX Pro)

A per-processor toggle on the VX400 Pro, VX1000 Pro and VX2000 Pro. Off (the default) a port's load is the circumscribed rectangle around its cabinets, so blank grid positions inside an irregular route still count against it — this is the NovaLCT model. On, loading is calculated from the actual physical cabinets, so creative walls, staggered layouts and non-rectangular routes stop spending capacity on empty space. The port bar, the routing limit and the reports all follow whichever model you pick, so they cannot disagree with one another. Classic VX / MCTRL / MSD / NovaPro senders keep the fixed NovaLCT behaviour.

2.3 Executing the Route

To begin mapping:

1
Select the output port Select the desired output port in the right-hand panel. The port will highlight, and a capacity progress bar will initialize.
2
Click the first target tile Navigate to the Canvas and click the first target tile. The capacity bar will immediately reflect the processing load.
3
Navigate with arrow keys To expedite workflow, utilize the directional arrow keys on your keyboard to rapidly navigate and route subsequent tiles, matching the industry-standard workflow of major processing software suites.
4
Press Tab for the next output When a port is full, press Tab to advance to the next port on the same processor and keep routing without reaching for the mouse — locked backup ports are skipped automatically, and the selection wraps around at the end. Shift + Tab steps back. The same key works in Circuit mode, moving through the circuits of the current Soca or folder.
⚠️
Modifying Routes To remove a tile from the active data chain, re-click the illuminated tile, or right-click and select Remove from Chain.

2.4 Interface View Options & Port Information

Collapsing the primary processor tab reveals the Port Info Tab for the actively selected port. This readout details remaining pixel capacity, total pixels used, tile ranges, and quick-action commands such as Reverse Data Chain and Clear All Tiles.

Display parameters can be customized via the View Options toggles. Connection paths, directional arrows, start/end markers, and chain labels can be enabled or disabled to optimize canvas readability.

2.5 Auto Router

For large, regular tile grids, right-click while routing a port to open the Auto Router. Choose from 8 serpentine presets (four starting corners, each horizontal or vertical) — the same pattern logic as NovaStar's Quick-Topo connection tool. The router maps the wall to a row/column grid and fills the port from the chosen corner, skipping tiles already routed to another port, until the port reaches its pixel capacity. Running the same preset on the next port continues the cable chain cleanly where the last one left off.

2.6 Replacing a Processor

When the rig changes — the MX40 you planned for becomes a VX1000, or a Tessera SX40 arrives instead of an S8 — right-click the processor and choose Replace Processor to swap the model while keeping your routing. It opens its own dialog rather than re-purposing the Add Processor form, so it is always clear you are replacing rather than adding.

Ports map one-for-one and carry their tiles and wall assignment across. A bigger model leaves the extra ports empty; a smaller one releases the surplus ports' tiles so you can reroute them. Modular targets — H Series cards, COEX CVT boxes — are configured right there in the dialog. Port names you typed by hand survive the swap; auto-generated ones follow the new model's convention.

💡
The cost is shown before you commit The dialog previews exactly what the swap will do — how many ports carry over, how many tiles would be released, and any port that would end up over capacity — with Cancel always available and a separate Replace anyway button for the case where tiles would be lost. One Ctrl+Z reverses the entire swap.

Power Distribution (Circuit Mode)

The Circuit Tab transitions the software from data topography to electrical load management, ensuring that power draw remains within safe operational limits.

3.1 Circuit Generation

Power infrastructure is added via the right-hand panel:

  • Single Circuits: Select the +1 icon to generate an independent circuit. The system will auto-sequence nomenclature if a custom name is not provided.
  • Soca Splays: Select the Soca button to introduce a standardized 6-circuit breakout bundle. Entire Soca bundles can be globally assigned to a specific wall to prevent cross-contamination of power documentation.

    A Soca's six circuits are created named after it — Soca A - 1 through Soca A - 6 — and renaming the Soca renames them with it: call it "Stage Left" and they become Stage Left - 1 … Stage Left - 6, each number staying on the same circuit. A circuit you renamed yourself is never clobbered — only names still in the auto-generated form follow along, so "House left truss" stays what you called it. One Ctrl+Z covers the lot.

3.2 Connector Tracking

Located beneath the circuit name is a connector badge. Clicking this cycles the physical connector type (Edison, PowerCON, True1). The software actively aggregates these connector profiles to generate accurate cabling manifests in the final production reports.

3.3 Electrical Load Calculations

Routing power follows the identical click-and-arrow methodology as data routing. As tiles are assigned to a circuit, the interface performs real-time load calculations. Both Wattage and Amperage are displayed, at both the low and high voltage set in Preferences. A global summary panel at the bottom left aggregates the total power draw to assist in specifying main venue distribution requirements.

An individual circuit's amperage is simply its total wattage divided by the voltage. A distro group, however, is reported as the current on its most heavily loaded line, which is what determines whether a breaker holds — see below.

Single-phase versus three-phase

On a single-phase distro every circuit sits on the same line, so the line current is the straightforward sum of all its circuits.

On a three-phase distro the circuits are distributed across the three phase pairs — A-B, B-C, C-A — in rotation as you add them, which is how a three-phase distro is loaded in practice. Each circuit's phase pair is labelled on its chip in the Circuit panel. Because the three legs are 120° apart, the current on any one line is not the arithmetic sum of the circuits on it; the software resolves each line with the standard delta vector calculation and reports the worst of the three.

⚠️
Why the three-phase number looks lower than you expect A balanced three-phase group reports roughly the raw total divided by √3 — about 58% of it. A 42-circuit distro totalling 1282.9 A of connected load shows 740.7 A per line, and that per-line figure is the one to compare against your breaker rating and to give to the venue. This is not a discount; it is the actual current each leg carries.

3.4 Advanced Branching: The "Twofer" Pro

To model parallel power splits, right-click the canvas during active routing and select Twofer Circuit. The system will prompt you to map Branch A. Upon completion, select Done with A and map Branch B. The Canvas will display a split-node icon, and the circuit panel will track both legs independently while maintaining the aggregate electrical load.

3.5 Circuit Groups & Distros

Organize circuits and Soca bundles into named, nestable groups — for example, a "Distro 1" group containing every circuit that feeds from a single venue distro. Create a group with the folder-plus icon in the Circuit panel; drag and drop circuits, Socas, or other groups into it to build up a hierarchy that mirrors how the show is actually powered.

Every group header shows a live rollup of its total circuit count and per-line amperage, visible even while collapsed. Optionally set an amp budget on a group — a breaker or distro rating — and the header displays dual low / high voltage load bars that color independently (green, amber, red) so an overloaded distro is obvious at a glance. The group path is also carried into the Production CSV and PDF reports as its own column.

Each group header carries a phase badge reading 1φ or 3φ. Click it to switch that distro between single- and three-phase; the load figures, the per-circuit phase-pair labels, and the load bars all recalculate immediately using the method described in 3.3. Set this to match the distro you are actually feeding from before reading any figure off the panel.

💡
Reports match the panel exactly The per-line amperage in the PDF's Circuit Requirements tree and the Max Load columns of the production CSV are the same numbers shown on the group header — including the three-phase calculation — so what you hand the venue matches what you designed against. Nested sub-groups keep their own independent totals, since each represents its own distro.
4

System Redundancy

The Redundancy Tab provides a controlled, isolated interface (the Redundancy Planner) dedicated exclusively to mapping failover data paths. On a large controller — an H Series chassis with fiber CVT boxes, or a fully populated COEX MX6000 Pro — the planner shows a drill-down tree instead of a flat wall of port chips, so a 120-port processor is still readable.

4.1 The Drill-Down Tree

Click a processor in the top picker to open it — up to three processors can be open at once, on a first-in-first-out basis. An opened processor grows into a bubble showing its output cards; click a card to reveal its CVT boxes and, inside each box, its individual ports. Cards and boxes that already carry a backup pairing show a badge on their header (backed up / backs up) even while collapsed, so you can see the overall protection state without drilling all the way down.

ℹ️
Whole-Processor Backups Are Excluded A processor that is already a full 1:1 backup of another (see 4.3) mirrors its partner completely, so it can't be opened for internal card/port pairing — there's nothing left to configure inside it.

4.2 Drag-Pair at Any Level

Drag any card, CVT box, or single port onto another one at the same level to pair every port inside it 1:1 by position:

  • Drag a CVT box onto another CVT box to back up every port in it, port-for-port.
  • Drag a whole output card onto another card to pair all of its CVT boxes (and their ports) in one move.
  • Drag a single port onto another port for a one-off failover line.

Pairing works within one processor or across two — but a cross-processor drag requires the target to be the identical processor model and configuration (same card layout, same CVT counts); a mismatched drop is blocked with an on-screen note rather than silently failing. When a card or box only has some of its ports already backed up, a new pairing fills the still-free ports first and only asks for confirmation before overwriting an existing pairing.

Quick-action buttons are also available to auto-assign Split or Sequential backup patterns across an entire processor's ports instantly. A red ⊗ on any card, box, or port clears its backup pairing.

⚠️
Routing Overrides If a port containing active tile routing is designated as a backup, the software will issue a collision warning. Proceeding will strip the data routing from the assigned tiles to free the port for failover duties.

4.3 Processor Mirroring

For primary/secondary controller configurations, drag the secondary processor icon entirely onto the primary processor icon within the planner. The software will automatically pair all corresponding outputs (Port 1 to Port 1, Port 2 to Port 2). To dissolve this relationship, right-click the paired entity and select Remove Backup Link.

Every backup pairing — whether a single port, a whole CVT box, a whole card, or a mirrored processor — flows straight into the data and power flow map exports, technical drawings, and the PDF report's Redundancy Plan page, which draws the same card/CVT-box tree as the planner itself.

The CSV and the PDF carry every kind of redundancy by name, not just controller-level 1:1 and N+1 pairs, and both state how each one is cabled — including that a mirrored trunk repeats the primary's chain in reverse. That is something a bare port list cannot convey, and getting it wrong on site means no backup at all.

4.4 Brompton Redundancy Wizard

A guided way to build a Tessera rig's redundancy, from a button at the top of the Redundancy window, above the controller grid. The drag-and-drop planner below it remains the manual alternative — the wizard is for getting a standard topology right quickly, not a replacement for hand-pairing.

Three steps: pick the method, pick the hardware, review what will be written.

  • Closed Loop — the wall's chain is cabled back on itself, so a break anywhere along it still leaves every panel fed from one end or the other.
  • Processor Redundancy — a second controller stands by for the first, taking over wholesale if it fails.
  • Mirrored Reverse — a second SX40 on the same XD boxes with the wall routed backwards.

Candidate loops are offered by each model's own rule, so most impossible configurations never appear on the menu at all: an SX40 offers "Trunk A loops back to Trunk B", an S8 offers its four port pairs. A validator catches the rest — trunk A paired with D, an S8 asked to do processor redundancy, a mirrored primary with nothing routed to it. Errors block Finish; warnings do not, and every issue prints its fix underneath rather than just refusing.

⚠️
Mirrored Reverse is a field technique, not a Brompton topology It is labelled as such in the wizard. It is not documented by Brompton — it is what crews do in practice, and it works, but you should know which of the three you are signing off on.

Finishing commits the groups, the port pairings and the processor roles as one undo. A port that becomes a backup has its tiles cleared, because it mirrors its primary rather than carrying its own load.

4.5 The Redundancy Plan List

Redundancy plan in the Redundancy window lists every group whatever its type — controller pairs, cable loops, mirrored trunks — each with its own delete button, plus Clear all redundancy to wipe the project's redundancy in one step. Previously only controller pairs were listed, so a closed loop or a mirrored trunk existed nowhere in the interface and could only be found by exporting the PDF.

ℹ️
No edit reaches beyond its own hardware The wizard's Finish supersedes the redundancy on the processors in its plan and leaves every other processor untouched — redoing your SX40s does not disturb an S8, an S4 or an M2. Pairing two processors clears only those two. Before committing, the wizard names the groups it would remove and the processors affected, and will not proceed until you agree; changing the selection withdraws that agreement.

Clearing really clears. The per-card, per-box and per-processor "Clear all" buttons used to drop the port pairings but leave the group behind still listing them — so the badges disappeared from the screen while the exported report went on describing redundancy that was no longer there. They now prune the group too, and drop it entirely once nothing is left in it. Every one of these is a single undo and marks the project unsaved.

Exports & Documentation

The Export Tab isolates the workspace to facilitate the generation of comprehensive project deliverables. Files may be exported individually or packaged into a unified ZIP archive by selecting multiple options.

5.1 Technical Maps & Diagrams

  • Canvas Export: Generates a geometrically accurate pixel map of the entire workspace. Features a "2x Scale" toggle to enhance legibility on small-pitch setups.
  • Pixel Map Export: Generates isolated maps per individual wall, optionally showing the approximate physical wall size (metric or imperial) on the wall badge. Display colors can be globally synchronized across all documentation.
  • Data Flow & Power Flow Maps: Crucial schematics for field deployment, available in Dark, Light, or Schematic (black-and-white technical) style. These maps can be watermarked with "Front View" or "Back View" overlays to dictate physical patching orientation, and show redundancy backup pairings as labelled badges — including the red BU.<port> marker on the last tile of each protected chain.
  • Technical Drawing: An SVG elevation of the wall with measurements, dimensioned edge by edge around the true outline rather than as a single bounding box — so stepped, L-shaped, and irregular builds are dimensioned the way they are actually constructed. Measurements follow the Metric or Imperial setting in Preferences and are derived from each tile's real manufacturer dimensions.

    On a canvas drawing, every wall is measured with its own panel pitch. A canvas that mixes LED products — a 2.6 mm header over a 3.9 mm side wall — is drawn with each cluster at its true physical size and in its true position relative to the others. Each wall is dimensioned once, overall width × height, rather than edge by edge: ~ before a figure means the wall is an exact rectangle at that size, and ≤ means it is irregular and the figure is its overall extent.

Annotation & colour options

  • Module Row/Column labels: prints each module's grid address in its top-left corner — row letter plus column number, so the top-left tile reads A1 and it counts A1 A2 A3 across and A1 B1 C1 down. Every wall is addressed from its own A1 origin, and rows past Z continue AA, AB. Invaluable for directing a crew to a specific panel over radio. Off by default.
  • Physical wall size: the wall badge can display the approximate physical size — 2M x 2M or 16'-3" — following your Measurement Units preference.
  • Per-wall colours: click the colour dot beside any wall in the Select Walls list to open a picker for that wall, with an ✕ to reset it to default. The chosen colours apply across Pixel Map, Canvas, and Data/Power Flow exports.

In the PDF report, every wall page lays its three maps out the same way: the info row on top, then Pixel Map, Data Flow and Power Flow stacked full width. Previously only walls wider than 2:1 stacked, and portrait or square walls put the three maps side by side in a narrow column — about 42 mm each on an A4 landscape sheet. Stacked, a map gets the full 273 mm of width, or most of a page's height when the wall is tall: more than twice as wide for a 9:16 wall. Tall walls use more pages as a result, which is the intended trade.

Every export runs on a background worker so the interface never freezes, with a live progress overlay showing the current step, a done/total count, and an estimated time remaining. Each export type remembers its own settings and wall scope independently — set a Light Data Flow Map for one wall and a Schematic Power Flow Map for all walls without one overwriting the other.

5.2 Data Reporting Pro

  • Production Report: Exports a comma-separated values (CSV) file containing granular metrics on total tile counts, pixel usage, power draw, and connector tallies. Its Circuit Group Distro table lists each distro's phase, rating, and maximum per-line load at both voltages, and the Processor Requirements table carries each processor's IP address.
  • PDF Report: The system natively outputs highly formatted HTML files. Opening this file in a standard web browser provides an optimized layout suitable for printing to PDF, ensuring superior typographical rendering and layout stability.

The PDF's Circuit Requirements section is laid out as a nested group ▸ Soca ▸ circuit tree rather than one long flat table, mirroring the structure of the Redundancy Planner. Each group bubble carries its phase badge, breaker rating, load percentage, and per-line amperage at both voltages; each Soca is an inner bubble with its connector type; and each circuit is a chip showing its colour, tile count, amperage at both voltages, and a twofer badge where the circuit splits.

Both documents say how many of each model the job needs, not just a grand total. The PDF's Processor Requirements page opens with an Equipment Required table — model, quantity, total ports, grand total on the last row — and the summary page's Processors card lists the models under the count. They are counted by model, so renaming two MX40 Pros "Upstage" and "Downstage" still reads as 2 × MX40 Pro rather than as two different types. Extension boxes (Tessera XD, CVT Box) are tallied separately, since they are ordered apart from the controllers that drive them.

A Drawn by option in the export settings adds a checkbox and name field; when enabled, "Drawn by: <name>" prints in the footer of every page of the report. The name is remembered between exports and across sessions, so it only needs entering once.

5.3 Quality Control Tools

The Test Card export generates SVG vector or PNG images scaled perfectly to your designated canvas or wall resolutions. These are utilized on-site for evaluating color temperature, black levels, and mitigating gradient banding.

5.4 Customization Pro

Within the export menu, users may upload a corporate logo. This asset will be automatically appended to all exported pixel maps, technical flow diagrams, and PDF reports for professional branding. The same logo can be uploaded from inside the Pixel Map Editor — there is only ever one shared logo, so setting it in either place sets it in both. The editor is also where you control where it sits on a pixel map and how big it is, or switch it off for a particular design.

5.5 EDID & Tearing Test Pro

  • EDID Export: Generate a custom-resolution EDID binary file for a wall or the whole canvas, to force a media-server GPU to output the exact pixel format. Auto-filled from the project's resolution, frame rate, and bit depth, with fields for plug type, reduced blanking, pixel encoding, color space, and HDR — validated byte-for-byte against professional EDID editors.
  • Tearing Test Video: Export an MP4 (or lossless PNG sequence) of the canvas pixel map with two sweeping sync lines. Play it on-site through a media server — if processors fall out of frame sync, the moving line visibly tears at the seam between them, pinpointing the problem before doors.

    A full Animation panel controls what sweeps: Effect (None, Scan Line, Sonar Line with a long fading tail, Screen Lines as marching bars, Center Pulse, or Ripple Waves as expanding rings at a constant stroke width), Direction (horizontal, vertical or both), plus Colour, Opacity, Speed, Line Size, Trail Length and Loops. Settings persist across sessions.
💡
The loop is seamless One cycle is a whole number of frames, both sweeps share a wrap distance, and the encoder is given an exact frame count rather than a duration that rounds at 23.98 / 29.97 / 59.94. Set the loop count and the file repeats with no visible seam — it can run on a media server all day without anyone noticing the join.

5.6 Pixel Map Editor Pro

Design how your pixel maps look, save it, and reuse it across projects. Open it from the header of the export window, beside the project name, or from the Pixel Map options. Live preview renders through the same engine as the export, so what you see is what the file will contain.

  • Colour: Dual or Triple mode, hue rotation with a colour bar showing what you are sliding toward, and a per-wall gradient with orientation, side, amount and feather. Dual mode shows two swatches; the third colour is still stored, so switching back to Triple loses nothing.
  • Images: two uploaded images can replace the two checkerboard colours outright.
  • Pattern: dial-able mosaic and X marks.
  • Centre badge: movable, scalable and rotatable — or removed entirely with the checkbox at the top of the section.
  • Module labels: restyled A1/B6 grid addresses, also removable with a checkbox.
  • Logo: placed anywhere at any size rather than pinned to a corner, uploaded from inside the editor, and switched off with a checkbox. It is the same single shared logo the export dialog uses — set it in either place and both see it.

Each section has a Default button that resets just that section, Ctrl+Z works inside the editor, and saved designs are renamed by double-clicking them. Designs sit alongside four built-in presets and are assigned per wall from a live-thumbnail picker in the export options, applying to both the Pixel Map and Canvas exports.

ℹ️
A design controls how a map looks, not what it contains What goes on the map — module labels, wall badges, annotations — stays with the export checkboxes. A label is drawn only when the export asks for it and the design has not switched it off, so the two never fight. The design picker only appears on exports that actually draw a pixel map.

5.7 Resolume Export Pro

Builds a Resolume Advanced Output preset from the project, so the map you have already planned becomes the screen setup instead of being rebuilt slice by slice in Arena. Each canvas becomes a screen at its own resolution and each wall becomes a slice, named after the wall and placed exactly where it sits on the canvas.

Non-rectangular walls keep their shape. An L, T or cross exports as a native Polygon with its true traced outline — the same tracer the technical drawings use — a wall of detached blocks becomes one slice per block so the gap is never mapped as wall, and an enclosed hole is reported rather than silently dropped.

Resolume holds one composition per preset while every LPM canvas starts at its own 0,0, so canvases are tiled side by side across the composition — each screen samples its own region instead of all of them stacking in the top-left corner.

  • Save preset as… writes the file anywhere you like.
  • Install to Resolume writes it straight into Resolume's Advanced Output presets folder, found automatically — OneDrive-redirected Documents included — with a Choose folder… fallback if your install is somewhere unusual.
ℹ️
Screens arrive as virtual outputs Assign the real display inside Resolume. Your live configuration is never touched, a replaced preset is backed up with a timestamp first, and every write is atomic — an interrupted save cannot leave you with half a preset.

5.8 Export Settings

File ▸ Export Settings… lets you choose exactly what an exported file contains, rather than sending the whole project every time. It saves as a normal .lpmap.

  • Project parts each get a checkbox: walls, tile profiles, annotations, processors, routing, circuits, circuit assignments, redundancy. Processors and routing are separate, so you can send someone the hardware without the patch — the devices and ports arrive with nothing assigned. Circuits and circuit assignments split the same way.
  • Canvases are a checkbox each, by name, rather than "this one or all of them".
  • Library items that never normally travel with a project can be included: My Tiles, My Processors, pixel map designs with their images, your branding logo, and preferences.

Dependencies are enforced and locked, so an export can never be self-inconsistent: routing pulls in both the processors and the walls, circuit assignments pull in the circuits and the walls, and redundancy needs only the processors. Presets cover the common cases — Everything, Share with a colleague, Layout only, Template — and never touch your canvas selection.

💡
Opening a file that carries library items You are asked first, and only what you do not already have is added. Someone else's saved tiles can never quietly overwrite yours.
